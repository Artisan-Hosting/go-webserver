# Email templates and theming

Every transactional email this server sends (owner notification, client
confirmation, and any future ones) is generated by
[Hermes](https://github.com/matcornic/hermes) (`github.com/matcornic/hermes`,
v1.3.0 — note this is the pre-`/v2` import path, pinned deliberately; see
`go.mod`). Hermes turns a small Go data structure (`hermes.Body{}`)
into a full HTML email.

The system has three layers:

1. **Content** — `email_templates.go`. Each email is a
   `hermes.Body{}` literal (`Intros`, `Dictionary`, `Table`, `Actions`,
   `Outros`, ...). No HTML.
2. **Layout** — `mailtheme.go`. One fixed HTML skeleton
   (`siteHTMLTemplate`) that all emails share. This is the only file in the
   project with hand-written HTML/CSS structure, and it should not need to
   change per site — only the CSS does.
3. **Appearance** — `theme/*.css`. A plain stylesheet that styles the
   fixed set of classes the skeleton exposes (below). Swapping this file (or
   pointing `MAIL_THEME_CSS` at a different one) reskins every email with no
   Go changes.

`renderEmail()` in `mail.go` ties these together: it builds one
`hermes.Hermes` engine (theme + product info) from environment config the
first time it's needed, and every `hermes.Email{}` passed to it renders
through that engine.

## Class-name contract

`theme/default.css` styles exactly these selectors. A new theme CSS
file should style the same set — the HTML in `mailtheme.go` isn't expected
to change to accommodate a new theme.

| Selector | What it styles |
|---|---|
| `body, html` | Base background/text color/font-family for the whole email |
| `a` | Link color |
| `.email-wrap` | Outermost full-width background table |
| `.email-masthead` | Top logo/product-name row, above the card |
| `.email-card` | The white card: background, border, radius |
| `.email-brandbar` | Thin accent bar across the top of the card |
| `.email-content-cell` | Padding around the card's body content |
| `.email-heading` | The `<h1>` title/greeting line |
| `.email-lead` | Intro paragraph(s), right after the heading |
| `.email-dictionary` | The label/value table (e.g. Name/Email rows) |
| `.email-dict-label` | Each row's label cell |
| `.email-dict-value` | Each row's value cell |
| `.email-table` | A data table (`hermes.Body.Table`); `th`/`td` inside it |
| `.email-button` | An action button (`hermes.Body.Actions[].Button`) |
| `.email-trouble` | The small "can't click the button?" fallback-link text |
| `.email-invite-code` | An invite-code chip (`hermes.Body.Actions[].InviteCode`) |
| `.email-outro` | Outro paragraph(s), after the main content |
| `.email-signature` | The closing "Yours truly, {Product}" line |
| `.email-footer` | Bottom footer: product link + copyright |

Structural rules that are *not* theme-controlled (table resets, `box-sizing`,
the mobile media query) live directly in `mailtheme.go` and are the same for
every theme.

## Configuration (per-deployment, no code changes)

Read from the process environment — normally via `.env`, loaded at
startup by `loadDotEnv()` (see `env.go`); real environment variables
always win over the `.env` file.

| Variable | Default | Effect |
|---|---|---|
| `MAIL_THEME_CSS` | `theme/default.css` | Path to the CSS file to load |
| `MAIL_PRODUCT_NAME` | `Artisan Studios` | Shown in masthead, footer, signature |
| `MAIL_PRODUCT_LINK` | `https://www.artisanhosting.net` | Masthead/footer link target |
| `MAIL_PRODUCT_LOGO` | *(unset — falls back to product name as text)* | Masthead logo image URL |

All paths are relative to the process's working directory, same as
`static`/`.env` elsewhere in this codebase — the server is expected
to run from the repo root (see `makefile`'s `run` target).

## Add a theme for your site

1. Copy `theme/default.css` to a new file (e.g. `theme/acme.css`).
2. Edit only the *values* (colors, fonts, spacing) — keep the same selector
   names from the contract table above.
3. Set `MAIL_THEME_CSS=theme/acme.css` and the `MAIL_PRODUCT_*`
   variables in `.env` (or the real environment).
4. Restart the server. No Go code changes, no rebuild required.

## Add a new transactional email

Write a function returning a `hermes.Email{}` and pass it to `renderEmail()`
— see `buildOwnerEmail`/`buildClientEmail` in `email_templates.go` for
examples. Available `hermes.Body` fields: `Title`, `Greeting`, `Name`,
`Intros []string`, `Dictionary []hermes.Entry{Key,Value}`,
`Table hermes.Table{Data, Columns}`, `Actions
[]hermes.Action{Instructions,Button,InviteCode}`, `Outros []string`. Never
write raw HTML for a new email — if the layout can't express what you need,
extend `mailtheme.go` (layer 2) instead, once, rather than hand-coding HTML
in the email function.

## For AI assistants

If asked to **add or reskin a theme**: read `mailtheme.go` first (the
class-name contract above is generated from it — trust the code over this
doc if they ever disagree) and `theme/default.css` as a working
example. Only add/edit a CSS file; do not modify the HTML in
`siteHTMLTemplate` for a reskin request. Keep new selectors within the
contract table — if a new visual element is genuinely needed, that's a
`mailtheme.go` change (affects every theme), call it out explicitly rather
than smuggling it into one theme's CSS.

If asked to **add a new email**: add a `hermes.Body{}`-returning function in
`email_templates.go` (or a new file, package `main`), call
`renderEmail()`, and wire it into whatever handler needs it — no HTML.

If asked to **change email copy/wording**: that's plain string literals in
`email_templates.go`'s `hermes.Body{}` fields — not a theme or layout
change.
